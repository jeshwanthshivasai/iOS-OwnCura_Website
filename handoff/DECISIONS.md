## 2026-10-25 13:12 IST: step 1 of the build order, the setup (Claude Code, branch `step-01-setup`)
- The Next app lives at the repository root beside `handoff/`: Next.js 16.4.3 (App Router, TypeScript 5.9.3, Turbopack), React 19.3.1 from npm, CSS Modules with the tokens in `app/globals.css`, no UI library. `app/page.tsx` renders the root alone for now; the sections follow in the build order.
- Fonts come through `next/font/google` and are self-hosted: Instrument Serif 400, IBM Plex Sans 400/500/600, IBM Plex Mono 400/500, Schibsted Grotesk 400/500/600. The four families v5's font link also loaded for options that are off (Space Grotesk, Newsreader, Bricolage Grotesque, Instrument Sans) are dropped, as the README asks. The page names its faces only through the tokens `--fd`, `--fb`, `--fm` (v5's names) and `--fs` for Schibsted Grotesk, and the motion engine reads `--fd` and `--fs` from the computed style for the canvas text measurements v5 makes with literal family names, so the markup never depends on what next/font calls a family.
- v5's `<style>` block is `app/globals.css` as it stands, plus the colour, type and easing tokens from README › Design tokens. v5's runtime also set `html, body { height: 100% }`; that is not carried over (the page scrolls the document, and the sticky stages do not depend on it).
- The motion engine is `lib/motion/engine.ts`: one requestAnimationFrame loop, smooth scroll updated first, then `tick`, with v5's cached lookups, write-once style setter, `prog`, `hq`, `stageY` and `fadeUp`. Sections attach to `tick` in page order as they are built. Smooth scroll is `lib/motion/smooth-scroll.ts`, v5's own (lerp 0.085), on only for a fine pointer with motion allowed. The easing helpers are `lib/motion/math.ts`.
- The WebGL helpers are `lib/gl/mesh-gradient.ts` (the living gradient, one shared context) and `lib/gl/dot-field.ts` (the dotted field, one shared context). `node tools/compare/helpers.mjs` draws them beside v5's in one Chrome page: 120 cases (three gradients and two fades of the field, four sizes, device pixel ratios 1 and 2, three frame times) are pixel-identical.
- Not built, because their switches are off: the custom cursor (`cursor` off) and the flat US map inside the dot field (`usMap` off). The base dot field therefore marks no dot as lit; the lit/position values stay in the shader for the footer's dotted name, which lights its letters through them.
- The values of the switches the code reads as numbers or colours are constants in `lib/settings.ts`, named after the README table.
- `tools/compare/screens.mjs` takes the side-by-side Playwright screenshots the README asks for (the seven sizes and 1920 × 1080 at device pixel ratio 2, every 5% through a section) using the installed Google Chrome; `npm run reference` serves v5 on port 3001. Screenshots land in `compare-out/`, which is not committed.
- `<html lang="en">` is set; v5's `<html>` has no lang attribute. Invisible; it tells screen readers and search engines the page is English.
- Two `.DS_Store` files that had been committed are removed from the repository; `.gitignore` keeps them out.
- There is no Vercel project for the repository yet, so no preview link exists until the designer imports it (README › Publishing on Vercel). Every push to `main` and to the step branches will then get its link.

## 2026-10-25 14:09 IST: step 2 of the build order, the nav, the intro and the hero (Claude Code, branch `step-02-hero`)
- Step 1 was approved and merged to `main` (13:45 IST).
- The nav is v5's hero nav on the glass bar: the logo, the word and the Get a valuation button in `[data-hero-row]`, moved between its states (inside the frame, edge to edge on glass, gone) by the motion engine. The README says `heroLinks` off hides "the nav's links and its Get a valuation button"; in v5 the switch hides only the five links (`[data-hero-links]`) and the button stays. v5 wins: the button is built, the links are not. The pill and island nav, the menu and the island's progress label are dead under the glass-bar setting and are not built.
- The hero's words are in the server HTML, under one h1. Their starting hidden states (the nav and the two lines) apply only once JavaScript runs, through a `data-js` flag an inline script sets on `<html>` before the first paint (README › SEO: hide text only with CSS that applies once JavaScript is running). The canvases and the earth start hidden regardless. The hero description is off and not built; the page's meta description keeps its words.
- "Skip intro" is in the server HTML and hidden until the intro runs; it ends the intro, as do the nav's anchors while it runs.
- The intro, the hero's exit into the resting H and the nav's states are `lib/motion/stage.ts`, with the object's shapes in `lib/motion/geometry.ts`, ported number for number. `tools/compare/intro.mjs` runs v5 and the build under one paused clock, stepped in 16 ms frames, so the intro's frames compare like for like at the eight sizes (the earth's 3 s rise is a CSS transition on the real clock, so frames after 8.25 s differ a little in the globe's height only).
- After the intro v5 sizes the resting H from 02's cards (a third of the first card's height, from the first stage frame after the intro); until step 3 brings the cards, the build uses the intro's base stroke, max(50, min(80, 0.067 × the height)). So in the exit frames (the frame shrinking back to the H) the build's H differs from v5's: it is taller at the sizes up to 1920 wide (by 6 to 26 px, the card stroke being 2 to 9 px smaller than the base) and shorter at 2560 × 1440 (by 36 px) and 3840 × 2160 (by 175 px, where the card stroke is 138 px against the base's 80). It will match once 02 is in.
- The earth is `lib/globe/globe.ts`: v5's delivered globe (`owncura-globe-page.js`) under the page's own hooks (the light palette, the US bands and state lines, the hold until the tiles are in). MapLibre comes from npm (5.6.0, byte-identical to v5's copy) with its stylesheet imported before the page's; the packed style and tiles, the US fill and outline and the state lines are JSON files in `public/globe/`, fetched with the library as soon as the page opens. Not built: the stars canvas (hidden in v5), the dotted land and its data file (`dottedLand` off), the cursor follow (v5 zeroes its range before it can act), and the 700 ms re-zoom at the end of the lab layers. That re-zoom served live changes of the `globeZoom` Tweak; the zoom is fixed at 3.7 and the entrance already lands on it. In the build the map starts only once the pack is fetched, and if that is more than 3.5 s after the reveal the re-zoom's `jumpTo` would stop the entrance and leave the globe flat (reproduced with a slow pack); v5 never hits this because its map starts at the reveal. Under reduced motion MapLibre makes the entrance instant in both, so that case is unaffected.
- The globe section is a `div` where v5 has a nested `section` inside the stage's section; nothing visible changes.
- The nav's anchors are `a[data-go]` handled by the engine (v5's `go`): the valuation and practices anchors land at the top until their stages exist.
- The nav's fixed sizes (the 1.35rem word, the 0.9375rem button) are v5's at 2560 and 3840 wide too; whether they read too small there is the designer's call (README › Screens).
- Open question for the designer: MapLibre's compact attribution control carries the map credit, as in v5, but the map is 100vh tall and starts 36vh down inside a clipped stage, so its bottom-right corner, where the control sits, is below the screen in v5 and in the build alike. The licence requires the credit to be visible; where it should show is the designer's decision.
- A review of this step (eight lenses, each finding challenged by three refuters) found and fixed: the intro's start was not cancelled when the engine was torn down, which under React's development-only double mount left a second intro loop running past "Skip intro" (production was unaffected); and the re-zoom above, which had been ported despite the entry's first wording.
- `AGENTS.md` at the root is written by `next dev` itself (a pointer to the installed Next.js docs for coding agents) and is re-created on every dev run; it is committed so the working tree stays clean. It holds nothing of ours.
